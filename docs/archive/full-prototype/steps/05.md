## 05. Подготовка реализации

> [!WARNING]
> Архивный шаг предыдущего полного прототипа; команда `openspec-orch load` удалена
> из текущей версии.

Шаг выполняет разработчик отдельно для каждой implementation subtask.

### 1. Получите параметры subtask

В subtask должны быть:

```yaml
parent_ticket: PAY-412
change_id: pay-412-payment-status
store_id: payments-specs
spec_baseline: 0123456789abcdef0123456789abcdef01234567
planning_pr: <planning-pr-reference>
repository_id: payments-api
work_packages:
  - "1"
  - "2"
```

Если обязательного поля нет, попросите Change Owner дополнить subtask. Не вычисляйте значения самостоятельно.

Если Work Packages несколько, можно выполнить их все за один подход или разделить на несколько рабочих сессий. Во всех случаях используются те же Change, subtask, implementation-ветка и PR.

### 2. Перейдите в Code Repository

```bash
cd <абсолютный путь до repository-id>
git status --short --branch
```

Рабочее дерево должно быть чистым.

### 3. Выполните `openspec-orch load`

Перенесите параметры из subtask без изменений:

```bash
openspec-orch load \
  --store payments-specs \
  --repo payments-api \
  --change pay-412-payment-status \
  --baseline 0123456789abcdef0123456789abcdef01234567 \
  --work-package 1 \
  --work-package 2
```

Для одного рабочего подхода можно передать только часть ID, например:

```bash
openspec-orch load \
  --store payments-specs \
  --repo payments-api \
  --change pay-412-payment-status \
  --baseline 0123456789abcdef0123456789abcdef01234567 \
  --work-package 1
```

### 4. Проверьте результат

Успешный вывод содержит:

```text
step_status: implementation_ready
repository_id: payments-api
implementation_branch: feature/pay-412-payment-status
work_packages: 1, 2
selected_tasks:
  - id: "1"
    description: "..."
next_step: 06
next_action: Сначала прочитай файл инструкций агента ".../<agent-instructions-file>". Затем прочитай и выполни инструкцию ".../sdd-apply.md" с параметрами: ...
```

Проверьте, что `repository_id`, Branch, Work Package ID и descriptions соответствуют subtask. Затем скопируйте строку `next_action` целиком: это первое сообщение новой агентской сессии на шаге 06.

Если команда завершилась ошибкой, выполните указанное в сообщении действие и повторите тот же `openspec-orch load`. Не исправляйте созданные служебные файлы вручную.

### Успешный результат

Переходите к [шагу 06](06.md), когда:

- `openspec-orch load` вернул `implementation_ready`;
- выбраны правильные Work Packages;
- активна ветка `feature/<change-id>`;
- у вас есть готовый `next_action`;
- код ещё не изменялся.

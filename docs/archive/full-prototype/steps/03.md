## 03. Подготовка Specs, Design и Tasks

> [!WARNING]
> Архивный шаг предыдущего полного прототипа; не используйте его в текущем процессе.

На этом шаге агент последовательно создаёт оставшиеся planning-артефакты. Отдельное согласование после каждого вызова не требуется: весь набор проверяется позже в одном Planning PR.

### 1. Проверьте Change

Из корня Store выполните:

```bash
openspec status --change <change-id> --store <store-id>
```

Proposal должен быть завершён, а следующим готовым артефактом должны быть Specs.

Если вы открыли новую агентскую сессию, запустите её из корня Store, чтобы агент загрузил project-level инструкции и subagents. Затем попросите агента показать полный Proposal и подтвердите, что это принятый вход шага.

Для зависимого Change перед созданием Specs выполните проверки из раздела [«Подготовка Change B»](../reference/changes.md#подготовка-change-b).

### 2. Продолжайте Change

Последовательно вызывайте одну команду:

```text
/opsx-continue <change-id>
```

Обычно потребуются три вызова:

1. Specs;
2. Design;
3. Tasks.

После создания Specs для `Modified Capabilities` проверьте выбранную Delta operation
по справочнику [«Работа с Changes»](../reference/changes.md#кто-выбирает-delta-operation).

Один Change может содержать несколько Delta Specs для одной бизнес-цели. Агент создаёт
по одному файлу на capability с сохранением её пути; пример приведён в разделе
[«Один Change с несколькими Delta Specs»](../reference/changes.md#один-change-с-несколькими-delta-specs).

Отдельно запускать Repository Context Pass не нужно. Если он потребуется, действуйте по
справочнику [«Работа с subagents при планировании Change»](../reference/subagents.md#как-запускается-repository-context-pass).

После успешного создания одного артефакта сразу вызывайте `/opsx-continue` снова. Останавливайтесь только если агент задал вопрос, сообщил об ошибке или обнаружил изменение согласованного scope.

Если агент создал неполный или противоречивый артефакт, попросите исправить текущий Change через:

```text
/opsx-update <change-id>
```

После исправления продолжите `/opsx-continue`.

### 3. Проверьте готовность

После последнего вызова выполните:

```bash
openspec status --change <change-id> --store <store-id>
```

Успешный результат показывает четыре завершённых артефакта:

```text
proposal: done
specs: done
design: done
tasks: done
```

### Успешный результат

Переходите к [шагу 04](04.md), когда:

- все четыре planning-артефакта имеют статус `done`;
- изменения находятся только внутри текущего Change;
- код, commit, push и PR ещё не создавались.

# Общий контекст продукта

`openspec/context/` центрального Store хранит единое описание бизнеса для всего
мультирепо-проекта. Количество репозиториев не определяет его структуру.

## Маршрут чтения

`openspec/config.yaml` направляет агента в `STORE.md`, затем в `00-start-here.md`
и только относящиеся к задаче разделы. Правила этапов и согласований находятся
в `openspec/process/quality-gates.md`, поставки — в `openspec/process/release-process.md`.
Актуальные инструкции артефакта определяются schema выбранного Change.

| Раздел | Содержание |
|---|---|
| `00-start-here.md` | Короткая навигация |
| `01-product-context.md` | Назначение, участники и их цели |
| `02-domain.md` | Специфичные термины и связи |
| `03-architecture.md` | Границы продукта, ответственность сторон и обмен информацией |
| `04-business-processes.md` | Начало, исполнители, крупные действия и результат |
| `05-constraints.md` | Единый список условий, включая бизнес-ограничения, данные, доступ и безопасность |
| `ADR/` | Значимые принятые решения, причины, альтернативы и последствия |
| `_raw/` | Исходные материалы для наполнения |

Каждый факт имеет одно место: определения участников — в 01, понятий — в 02,
условия — в 05. Новая редакция заменяет условие, закрытые вопросы удаляются.
Самодостаточен весь каталог: разделы дополняют друг друга через внутренние ссылки,
происхождение внешних сведений записывается текстом.
Подробные требования и критерии приёмки принадлежат Master Specs.

## Два режима наполнения

Вызовите команду внутри агента:

```text
/spec-driven-extended-context initialize
/spec-driven-extended-context update
```

`initialize` формирует первоначальное описание, сохраняя уже заполненное.
`update` добавляет сведения и исправляет устаревшие записи в рамках цели.
Без режима пустой шаблон означает initialize, наличие сведений о продукте — update.
Проверка согласованности входит в оба режима; отдельного audit больше нет.

Необязательные `--change <change-id>`, `--spec <capability-path>` и
`--domain <domain-path>` ограничивают источники. Повторные selectors объединяются.
Команда не зависит от schema и не требует Change или Specs для первоначального описания.

Агент сначала читает контекст и исходные материалы, сообщает найденное, затем задаёт
по одному вопросу о пробелах. Вопрос можно пропустить. При дополнении полное интервью
не повторяется. Неподтверждённое записывается как TODO: что выяснить, у кого и по какому
источнику. Размещение материала в `_raw/` не подтверждает его принятие.

После блока агент показывает буквальные фрагменты «до» и полный текст «после».
После отдельного подтверждения применяет только эти замены и сравнивает полные файлы
с ожидаемым результатом. Исходные материалы и текст вне замен остаются нетронутыми.
После записи проверяются смысл, внутренние ссылки и отсутствие повторов. Если менять
нечего, запись и согласование не нужны. Итог — сохранённые разделы, ADR, оставшиеся
вопросы и непрочитанные нужные источники, без обязательного YAML-отчёта.

В содержательных документах `owner` обозначает владельца раздела (`unassigned`,
если неизвестен), `updated` — дату фактического изменения (`null` в пустом шаблоне).
Это не подтверждение принятия всех сведений. Действующее и принятое целевое состояние
различаются явно. Применимость политик и исключений подтверждает ответственный владелец.

## ADR

ADR сохраняются для решений о границах продукта, ответственности, взаимодействиях
и ограничениях. Один файл — одно значимое принятое решение с обоснованием.
Шаблон находится в `context/ADR/README.md`; имя — `NNNN-short-title.md`.
Наличие Change не обязательно. Действующее описание остаётся в тематическом разделе,
ADR объясняет выбор. Непринятое предложение остаётся вопросом.

## Обновление существующего Store

Template копируется при первом init; повторные init и connect не мигрируют контекст.
Обновление уже заполненного Store требует отдельного согласованного изменения:
сохраните существующие знания, распределите их по разделам и проверьте входящие ссылки.
Сведения вне области общего контекста сначала согласованно перенесите в подходящее
место; не удаляйте единственную запись. Имена существующих файлов не меняйте молча.

При переносе этой версии обновите одновременно маршрут в `openspec/config.yaml`,
`STORE.md` и документ `openspec/process/quality-gates.md`: туда перенесены прежние
инструкции согласованности этапов. Сохраните роли и правила проекта. Обновите Extension,
затем используйте `update` для проверки и согласования нужных изменений контекста.

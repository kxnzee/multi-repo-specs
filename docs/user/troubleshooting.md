# Диагностика и восстановление

## Первый шаг

```bash
openspec-orch doctor
```

`doctor` ничего не меняет. Он показывает проблему и, если способ исправления
известен, точную команду в разделе «Дальше». Машиночитаемый отчёт выдаёт `doctor --json`.

## Перед восстановлением

1. Остановите команды и процессы агента и MCP, которые используют Store.
2. Сохраните копию `<workspace>/specs/` вместе с `.openspec-orch/`, вывод `doctor --json`, версии
   Node.js, OpenSpec и Orchestrator, точный текст ошибки и `git diff`.
3. Не удаляйте `<workspace>/specs/.openspec-orch/` целиком: там может быть состояние незавершённой работы.

## Ошибки и действия

### Создание и конфигурация Store

| Ошибка | Что делать |
|---|---|
| `needs_recovery` после первого `init` | Сохраните каталог: повторный `init` не ремонтирует Store. В чистой копии того же коммита повторите `init` с теми же параметрами, сравните с сохранёнными файлами и перенесите данные вручную. Если Store ID занят, сначала разберитесь с регистрацией в OpenSpec |
| `INIT_TARGET_INVALID` | `init` через MCP вызван не из корня Store. Откройте сессию агента в каталоге Store |
| `STORE_AGENT_MISMATCH`, `STORE_TEMPLATE_MISMATCH` | Используйте агента и Template, записанные при создании Store. Сменить их можно только отдельной миграцией |
| `CONFIG_INVALID`, `SPECS_CONFIG_INVALID`, `STORE_IDENTITY_MISMATCH` | Восстановите конфигурацию и метаданные из одного принятого коммита Store. Пакеты не восстанавливайте, пока конфигурация не читается |

### Пакеты плагинов и расширений

| Ошибка | Что делать |
|---|---|
| `package status`: `stale` или `unavailable`; `PACKAGE_RUNTIME_STALE`, `PACKAGE_RUNTIME_UNAVAILABLE` | Проверьте `package.json` и `package-lock.json`, выполните `package sync`, затем `connect` и `doctor`. В `--json` недоступная среда имеет состояние `missing` |
| `PACKAGE_SOURCE_MUTABLE` | Замените источник точной версией, архивом или коммитом через `plugin update` или `extension update`, затем `connect` |
| `PACKAGE_SUPPLY_INVALID`, расхождение `package.json` и `package-lock.json` | Восстановите оба файла из одного принятого коммита. `.openspec-orch` и `.openspec-orch/packages` должны быть обычными каталогами, не ссылками |
| `PLUGIN_LOAD_INVALID` с требованием `restart` | Перезапустите процесс CLI/MCP после `package sync` или обновления пакета |

### Файлы агента в репозиториях

| Ошибка | Что делать |
|---|---|
| `AGENT_PACK_CONFLICT` | Файл OpenSpec в репозитории отличается от Store (LF/CRLF не считается). Сверьте указанный путь и согласуйте обновление; `connect` такой файл не перезаписывает |
| `AGENT_PACK_DRIFT` | `doctor` нашёл отсутствующие, изменённые или устаревшие файлы. Обновите их через изменение Store и выполните `connect`. Сам `doctor` файлы не трогает |

### Шлюз и расширения агента

| Ошибка | Что делать |
|---|---|
| `AGENT_EXTENSION_STATUS_MISSING`, `_DISABLED`, `_SCOPE_MISSING`, `_STALE` | Шлюз: `agent setup --agent <id> --refresh`. Standalone Extension: `extension connect <extension-id> --refresh`. Extension плагина: `plugin connect <plugin-id> --repo <repository-id>`. Затем `status`, `doctor` и новая сессия агента |
| `AGENT_EXTENSION_STATUS_PROJECT_MISMATCH` | Проверьте проект, источник и область установки в CLI агента. Не правьте служебные файлы и не используйте `--refresh`, пока причина не ясна |
| `PROJECT_CONNECT_NOT_READY` | Исправьте статус плагина или расширения, указанный в `doctor`, и повторите `connect`. Уже выполненные подключения сохраняются |

### Прерванные операции

| Ошибка | Что делать |
|---|---|
| Код ошибки оканчивается на `_BUSY` при остановленных процессах | В ошибке указан путь к каталогу блокировки. Убедитесь, что процессы остановлены, и удалите только этот пустой каталог командой `rmdir` |
| Код ошибки оканчивается на `_ROLLBACK_FAILED` | Сохраните обе ошибки, проверьте состояние через `status` и `doctor`. Не повторяйте операцию вслепую: восстановите ресурс по инструкции плагина или расширения |
| Повреждённое состояние или неизвестная версия формата | Сохраните файл и восстановите проверенную копию той же версии. Номер версии вручную не меняйте, записи незавершённой работы не удаляйте |

Полный список кодов завершения есть в [справочнике CLI](../core/reference.md#коды-завершения).

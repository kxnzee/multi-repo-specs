# 4. Archive

Archive переносит принятую дельту Change в Master Specs и закрывает Change.
Выполняется в Store-сессии после успешного Verify.

**Кто:** аналитик ([роли](../story-delivery-process.md#роли)).

[← Verify](verify.md) · [Обзор этапов](README.md)

## Перед началом

- Verify завершён с решением человека `PASS`.
- Код всех репозиториев принят в целевые ветки по процессу команды.
- Все изменения Store по этому Change (Planning, задачи, `verify.md`) приняты.

## Запуск

Вызовите `/opsx-archive <change-id>` из Store-сессии. Агент читает условия Archive из инструкций
schema и проверяет требуемые решения людей. Ветки и направления PR агент не
угадывает: они берутся из правил проекта, а если правил нет, их уточняют у команды.

Archive меняет Store. Оформите его отдельным PR по процессу команды.

## Зависимые Changes

Если подключён плагин [OpenSpec Graph](../../plugins/openspec-graph.md), проверьте
граф до и после Archive:

```bash
openspec-orch plugin exec openspec-graph inspect --json
```

Зависимые Changes архивируются в порядке зависимостей.

## Что Archive не делает

- Не выполняется автоматически ни Orchestrator, ни плагином, ни агентом.
- Не подтверждает развёртывание и не разрешает выпуск. UAT и выпуск следуют
  правилам проекта.
- Master Specs не редактируются вручную: если после Archive найдено несоответствие
  архивированному Scenario, создаётся новый корректирующий Change.

Пример полного цикла от Jira Story до выпуска есть в
[процессе работы над Jira Story](../story-delivery-process.md).

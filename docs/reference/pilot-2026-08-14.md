# Изолированный пилот OpenSpec Orchestrator — 2026-08-14

## Результат

Пилот пройден на реальном OpenSpec CLI `1.7.0` и Node.js `20.13.1` в strict mode. Проверены два независимых сценария:

1. встроенный Template, Store и два Code Repositories: `init -> connect -> change -> load -> Apply handoff`; `change` выполнен без зависимости от Explore;

## Пользовательский Template и кастомная схема

Второй Template был обычным каталогом без package/lifecycle. Он:

- выбрал agent ID `team-agent` и официальный adapter `qwen`;
- перенёс официальный pack `.qwen -> .team-agent`;
- установил собственные `TEAM.md` и `.team-agent/actions/team-apply.md`;
- не содержал `CODEOWNERS`, `.sdd/` или context pack;
- установил project-local `openspec/schemas/research-only/schema.yaml` и выбрал его через `openspec/config.yaml`.

OpenSpec подтвердил `Source: project` и валидность `research-only`. Схема содержит единственный artifact `briefs/change.md`, не содержит `proposal.md`, `design.md` или `tasks.md`, а Apply требует только `brief`.

| `custom-specs` Planning baseline | `77fefd9dbce583b854933fd4740a30cfe7f3a6e7` |
| `custom-service` | `608d163dc2d782378e2c425bcabbc887a40ad6fc` |

Ключевые команды:

`init`, `connect` и `change` запускались из
`/private/tmp/openspec-orch-stage7-20260814-1/custom-workspace/custom-specs`; `load` — из

`change` вернул schema `research-only` и следующий artifact `brief` по структурированному ответу OpenSpec. Поскольку схема не возвращает Tasks, `load` не потребовал `--work-package` и подготовил `implementation_mode: whole-change`. `next_action` использовал пути именно пользовательского Template. После повторной OpenSpec validation и Apply instructions в разрешённом `custom-service` создан и проверен `implementation-marker.json`; immutable Store остался чистым на точной Baseline.

Этот сценарий сначала выявил зависимость поиска Store от `00-start-here.md` и `system-map.yaml` базового Template. Требование удалено из Core и закреплено regression test: пользовательский Template теперь может не содержать context pack.

## Границы результата

- Использованы локальные bare Git remotes; hosted PR, branch protection и проверки конкретного Git-провайдера не проверялись.
- Setup PR был воспроизведён commit/push созданного `openspec/config.yaml`, после чего повторный `connect` вернул `ready`.
- Apply handoff фактически прочитан и выполнен до локальной проверенной реализации, но implementation commits/PR не создавались: handoff прямо требует отдельного поручения для этих внешних действий.
- Composite Verification, rollout, Archive и будущие Plugins не входят в этап 7.
- OpenSpec schema API `1.7.0` помечает команды управления схемами как experimental; Core поэтому опирается на фактические публичные JSON-ответы рабочих команд, а не на собственную модель schema.

## 00. Инициализация и подключение

Проект создаёт один раз Technical Owner. Остальные участники только подключают свою рабочую машину.

### Подготовка CLI

Перед работой со спеками установите команду `sdd` из текущего репозитория:

```bash
cd harness
npm install
npm link
hash -r
```

Проверьте окружение:

```bash
node --version
openspec --version
type -a sdd
sdd --help
```

Требуются Node.js 20+ и OpenSpec 1.7.0. Первым в выводе `type -a sdd` должен быть CLI,
связанный с каталогом `harness` текущего репозитория. После смены версии Node.js через NVM
повторите `npm link`.

На этом этапе спеки не создаются. Центральный Store со спеками создаётся или подключается
отдельно по инструкции ниже.

Чтобы получить обновления, выполните из корня этого репозитория:

```bash
git pull --ff-only
cd harness
npm install
npm link
hash -r
```

После успешного `sdd --help` создайте или подключите Store по инструкции ниже.

### Настройка языка AI-агента

В интерактивной сессии каждого используемого Qwen Code-совместимого клиента один раз
задайте русский язык ответов:

```text
/language output Russian
```

Перезапустите клиент, чтобы настройка применилась. Текущее значение можно проверить
командой `/language`.

При необходимости отдельно переключите на русский язык интерфейс CLI:

```text
/language ui ru-RU
```

Для работы процесса важен `output` — язык ответов агента. Настройка `ui` меняет только
меню, подсказки и системные сообщения CLI.

### Создание нового проекта

Из чистого центрального Git-репозитория выполните:

```bash
sdd init \
  --store <store-id> \
  --agent <agent-id> \
  --repo "<repository-id>=<git-url>#<default-branch>" \
  [--repo "<repository-id>=<git-url>#<default-branch>"]...
```

Пример:

```bash
sdd init \
  --store payments-specs \
  --agent <agent-id> \
  --repo "payments-ui=git@github.com:company/payments-ui.git#main" \
  --repo "payments-api=git@github.com:company/payments-api.git#main"
```

Каталог, в котором запускается `sdd init` (или путь, переданный команде), является каталогом Store. В стандартной структуре имя этого каталога совпадает со `store-id`, а его родитель является workspace.

После команды:

1. заполните созданный `CODEOWNERS` реальными владельцами;
2. выполните команду подключения, которую напечатал `sdd init`;
3. если команда потребует setup PR для Code Repository, создайте и слейте его;
4. запустите `/sdd-context` в поддерживаемом AI-агенте из корня Store;
5. проверьте изменения и слейте initialization PR;
6. обновите локальный checkout и ещё раз выполните `sdd connect`.

## Когда обновлять контекст повторно

Контекст проекта поддерживается и после инициализации. Когда его нужно пересматривать и куда направлять новые сведения, описано в справочнике [«Когда пересматривать документацию и контекст»](../reference/instruction-and-context-zones.md#когда-пересматривать-документацию-и-контекст).

Стандартная структура выглядит так:

```text
<workspace>/
├── <store-id>/
│   └── openspec/
└── src/
    └── <repository-id>/
```

Пример:

```text
C:/work/rum-multirepo/
├── rum-specs/                  ← Store, store-id: rum-specs
│   ├── .openspec-store/
│   │   └── store.yaml
│   ├── sdd.yaml
│   └── openspec/               ← context, specs и changes
└── src/                        ← Code Repositories
```

SDD определяет workspace автоматически, только когда имя каталога Store точно совпадает со `store-id` из `.openspec-store/store.yaml`. Родитель этого каталога становится workspace. В примере выше:

```text
Store ID:        rum-specs
Store:           C:/work/rum-multirepo/rum-specs
Workspace:       C:/work/rum-multirepo
Code Repository: C:/work/rum-multirepo/src/<repository-id>
```

Каталог `src` и недостающие checkout создаёт `sdd connect`; вручную создавать их не нужно.
Во время проверки и клонирования команда показывает текущий репозиторий. Не прерывайте её,
пока не появится итоговый `connect_status` или сообщение об ошибке.

В конце `sdd init` печатает готовую следующую команду. Для стандартной структуры это
`sdd connect`, а при несовпадении имени каталога и `store-id` — `sdd connect --workspace`
с абсолютным путём родительского каталога Store.

Для нестандартного расположения, смены workspace или уже существующей локальной
регистрации Store используйте справочник
[«Подключение Store в нестандартных ситуациях»](../reference/store-connection.md).

### Подключение участника

Если проект уже создан, не запускайте `sdd init`. Выполните:

```bash
git clone <store-git-url> <workspace>/<store-id>
cd <workspace>/<store-id>
sdd connect
```

При нестандартном расположении Store или ошибке локальной регистрации продолжите по
справочнику [«Подключение Store в нестандартных ситуациях»](../reference/store-connection.md).

### Успешный результат

Переходите к [шагу 01](01.md), когда:

- `sdd connect` вернул `connect_status: ready`;
- все нужные Code Repositories доступны в `<workspace>/src/`;
- setup и initialization PR слиты;
- рабочие деревья чистые.

Если команда остановилась, выполните указанное в сообщении действие и повторите её. Не удаляйте локальные изменения ради продолжения шага.

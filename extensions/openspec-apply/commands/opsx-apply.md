# Repository-scoped Apply

Выполни одну Task существующего OpenSpec Change в текущем Code Repository. Команда
не ведёт Planning, не редактирует Store и не объединяет несколько Tasks в один commit.

## 1. Получить актуальное назначение

Требуй точный `<change-id>`. Вызови MCP `get_change_context` с `artifact: "apply"`
и `include_assignment: true`. Если MCP или обязательное поле недоступны, остановись;
не используй OpenSpec CLI и не читай Store по файловому пути как fallback.

Проверь одновременно:

- Change существует, Apply разрешён актуальными artifact instructions;
- `current_assignment.role` равен `code`;
- assignment указывает на текущий checkout и repository-id;
- scope готов, а текущему Repository назначена незавершённая Task.

Несовпадение Repository, неготовый Planning, новый scope или неоднозначный checkout —
blocker. Не расширяй файловые разрешения и не переходи в соседний Repository.

## 2. Прочитать спецификации через MCP

До реализации прочитай все ресурсы из `context_resources`: это серверное
сопоставление `artifact_instructions.contextFiles` с опубликованными ресурсами.
Для каждого ресурса вызови MCP `read_spec_resource` с его точным `uri`.
`resources` и `shared_resources` содержат только descriptors, а не текст файлов:
через тот же tool прочитай относящиеся к Task Master Specs и общий контекст.
Сохрани прочитанный текст и `_meta.content_revision` в рабочем контексте.

Пути из `contextFiles` — метаданные OpenSpec, не разрешение на файловое чтение.
Инструкции вида «read context files» выполняй через `read_spec_resource`, даже
если они содержат абсолютный путь. Не вычисляй URI самостоятельно и не передавай
путь в файловые инструменты, shell или CLI. При отсутствии `context_resources`,
нужного ресурса, tool или текста остановись с точной ошибкой до изменения кода.
Ранее прочитанный текст можно использовать только при подтверждённой актуальности
его ревизии; ответ `unchanged: true` без сохранённого текста требует полного чтения.

## 3. Выбрать одну Task

Из `artifact_instructions.tasks` выбери только первую незавершённую Task текущего
Repository. Сохрани её opaque `task_id` буквально; не вычисляй ID из номера или текста.
Если в рабочем дереве уже есть несвязанные изменения, сохрани их и исключи из
будущего commit. При пересечении с Task остановись и запроси решение пользователя.

Кратко сообщи выбранную Task, ожидаемый результат и проверки. Затем исследуй и меняй
только текущий Repository. Соблюдай его инструкции навигации и разработки; если
доступен актуальный CodeGraph — используй его первым, иначе выполняй адресный поиск.

## 4. Реализовать и проверить

Внеси минимальное изменение для одной Task и выполни относящиеся к ней тесты и
статические проверки. Не начинай следующую Task, даже если оставшегося контекста
достаточно. Не меняй checkbox в Store и пока не вызывай `set_task_completion`.

Проверь diff этой Task. Покажи пользователю:

- выполненную Task и затронутые файлы;
- результаты проверок и известные ограничения;
- точный состав предлагаемого commit и сообщение commit;
- несвязанные изменения, которые останутся вне commit.

Задай один прямой вопрос о согласии создать этот commit и остановись. Молчание,
предыдущее согласие на Apply или общий запрос «реализуй Change» не являются согласием
на commit.

## 5. Завершить только после явного согласия

После явного согласия перечитай status/diff, добавь в index только файлы этой Task и
создай ровно один commit с согласованным сообщением. Не выполняй push, rebase, merge
или reset без отдельного запроса. Если состав diff изменился, снова покажи его и
запроси согласие; не используй прежнее подтверждение.

Убедись, что commit создан и содержит только эту Task. Затем вызови MCP
`set_task_completion` с точными `change_id`, сохранённым opaque `task_id` и
`completed: true`. При отказе MCP не редактируй Store вручную: верни commit hash и
точную ошибку как handoff.

После успешной записи обнови Apply context через `get_change_context`, сообщи commit
hash и статус Task. Даже если следующая Task доступна, остановись: её реализация и
commit требуют отдельной итерации и нового человеческого согласования.

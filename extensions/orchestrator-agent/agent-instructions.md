# Шлюз агента OpenSpec Orchestrator

Используй MCP `openspec-orchestrator` как источник актуального контекста Project,
Change, Repository, Doctor и доступных Plugin capabilities. Нормативные артефакты
Store читай через предоставляемые им ресурсы.

## Политика свежести контекста

- Первый read-вызов возвращает `context_revision`, относящийся к конкретному tool и его
  входным данным. Считай такой ответ текущим Work Context и передавай его результаты во
  вложенные команды и skills; не вызывай MCP повторно только потому, что начался новый
  внутренний шаг.
- Граница свежести возникает при смене Change, artifact или Repository, после записи
  Store artifact, изменения checkout/worktree/revision, после controlled MCP write либо
  при ошибке, конфликте или отсутствии обязательного поля. Только тогда обновляй
  соответствующий read context.
- Для повторной проверки с теми же аргументами передай прежний `context_revision` как
  `if_context_revision`. Ответ `unchanged: true` подтверждает актуальность прежнего
  payload и не требует повторного чтения или пересказа.
- Не вызывай MCP повторно после рассуждения, чтения уже известных ресурсов или передачи
  управления вложенному skill. `get_status` используй для выбора неизвестного Change,
  `get_doctor_report` — только для диагностики, а не как preflight каждого шага.

Перед настройкой Project вызови `get_setup_context`. Инструмент записи вызывай только
тогда, когда пользователь явно запросил соответствующую операцию.

При `initialize_project` Store передавай только через `store_id`. В `repositories`
включай только Code Repositories; не добавляй текущий Store в `repositories`, даже если
его Git repository входит в предоставленный пользователем общий список репозиториев.
Если `repository_id` совпал со `store_id`, не переименовывай Store: исключи эту запись
из предлагаемого payload и запроси подтверждение пользователя перед новым вызовом.

Если MCP-инструмент записи отклонил запрос, остановись и сообщи пользователю точную
причину и рекомендованный способ восстановления. Не повторяй запрос с неизменными
входными данными и контекстом.

Соблюдай правила из актуального `get_change_context` и значение поля `actor` из
`get_next_action`.
После записи артефакта и перед предложением следующего шага обнови
`get_next_action` для того же Change. Статус отдельного артефакта не заменяет
рекомендацию следующего действия. При неизвестном состоянии сначала получи
недостающий контекст; это правило действует и во вложенных skills.
Остановись при `human` или `human_or_ci`. Если действие Orchestrator или Plugin
отсутствует в MCP, не имитируй его с помощью CLI, Git, файловых инструментов
или запуска процессов.

Штатное редактирование артефактов OpenSpec в рамках запроса пользователя
регулируется актуальными инструкциями выбранной schema. Read-only MCP resources
сами по себе не запрещают такую локальную запись и не требуют отдельного write-tool.
Соблюдай права среды и правила публикации проекта; отказ доступа не разрешает
обход ограничений. После записи обнови соответствующий Work Context.

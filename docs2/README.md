# OpenSpec Orchestrator — документация v2

Этот каталог — самостоятельная документация текущей реализации OpenSpec
Orchestrator. Источник правды — код, схемы и тесты репозитория. Материалы из `docs/`
отфильтрованы: действующие правила перенесены и уточнены, дубли удалены, исторический
PoC и еще не реализованные интеграции не включены в рабочие инструкции.

## Нормативная граница

OpenSpec владеет Requirements, Scenarios, Changes, Apply и Archive. Orchestrator
подготавливает Store и workspace, проверяет Git/OpenSpec-контекст и предоставляет
общую Plugin Platform. Project Template задает проектный процесс. Plugins добавляют
собственные данные, команды и проверки, но не становятся новым источником требований.

Core не выполняет `git add`, `commit`, `push`, `merge`, `rebase`, PR, deployment,
проектные тесты, ручную проверку, Release или Archive. Эти действия явно остаются у
пользователя, команды, OpenSpec или внешних систем.

## Что было отфильтровано

- исторический `docs/archive/reference/OpenSpec для команды.md` сохранен только как
  provenance и не используется как runbook;
- проектные примеры с вымышленными backend/frontend и устаревшей OpenSpec grammar не
  перенесены;
- Jira, Zephyr и Confluence оставлены за границей действующего продукта: adapters в
  репозитории отсутствуют;
- повторяющиеся описания одного flow сведены в один пользовательский маршрут и набор
  отдельных сценариев;
- точные форматы и ограничения, которые важны только разработчику, вынесены из
  пользовательского раздела в `technical/`.

## Достоверность

Комплект отражает текущее рабочее дерево после сверки с кодом. Локальный `npm run check`
подтверждает code tests, integration tests и structural checks Template/agent
artifacts. Он не доказывает совместимость со всеми будущими версиями внешнего
OpenSpec CLI, реальным Git hosting, нативным CodeGraph runtime или каждым provider
runtime. Core требует semantic version от `openspec --version`, но не задает minimum
или exact pin.

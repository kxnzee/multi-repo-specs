### Дни 3–5 (Слой E: `sdd setup/fetch-repos/load/check`) — в процессе

- Сделано: реализация CLI в `harness/` (Node.js, `commander` + `js-yaml`), первый коммит кода обвязки — Часть III регламента скопирована в `harness/SPEC.md` по правилу 0.4, синхронной парой с этим коммитом
  - `sdd setup` — честно печатает число областей/активных изменений, реестр хранилищ в `~/.sdd/registry.json` (машинное состояние, не в git)
  - `sdd fetch-repos --change <id>` — читает `candidate_repositories`, ведёт `read-log.md`, клонирует в `.sdd-clones/<change-id>/` (в `.gitignore`), fail closed при отсутствии адреса в `harness/repos.yaml`
  - `sdd load <change-id> --repo <name>` — три причины отказа реализованы (нет изменения / нет WP / нет Baseline), пишет `.sdd/change.yaml`
  - `sdd check change <id>` — правило 1 (обязательные артефакты, схема `impact-and-design.md`, Work Packages по правилу 3)
  - `sdd check code --path <repo>` — правила 4 (карточка, имя и тип тега, достижимость) и 5 (нет своего корня OpenSpec)
  - Пре-коммит-хук `harness/hooks/pre-commit` + установщик `harness/scripts/install-hooks.sh`
  - 11 тестов, `npm test` в `harness/`, зелёные — включая обязательные негативные случаи (невалидная фикстура `pilot-004`, lightweight-тег, чужой `openspec/` в кодовом репозитории)

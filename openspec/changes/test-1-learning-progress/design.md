## Context

См. proposal.md — Why и What Changes.

Артефакты курса хранятся в человекочитаемом формате Markdown. Фреймворк обучения не предоставляет программного интерфейса для внешнего потребления прогресса — в рамках Explore не обнаружен (grep: 0 результатов по `json|api|export|endpoint` в `.md`). Репозиторий `page` не содержит кода (только `README.md`).

## Goals / Non-Goals

**Goals:**

- Зафиксировать межсистемный контракт: кто поставляет данные, кто потребляет, каков формат
- Определить совместимость и миграцию
- Определить порядок поставки и откат

**Non-Goals:**

- Добавление программного интерфейса в фреймворк обучения
- Изменение формата артефактов курса
- Отображение данных за пределами статусов модулей (понимание тем, ошибки, следующий шаг)

## Межсистемные ответственности

- **`learning-method-framework`** владеет артефактами курса и контрактом статусов. Контракт статусов состоит ровно из трёх значений: `пройден / в процессе / план`. Фреймворк определяет и валидирует формат артефактов.
- **`page`** отвечает за потребление артефактов курса и отображение статусов модулей. Локальный способ реализации page здесь не определяется.

## Контракт данных

Контракт статусов модулей: `пройден / в процессе / план`. Источник контракта — спецификация фреймворка (`core/SPEC.md` раздел 3, `validate.py` строка 18). Потребитель (`page`) принимает контракт без расширения и без преобразования.

## Совместимость

- Формат артефактов курса не является стабильным контрактом для внешних потребителей. Если формат изменится в будущей версии спецификации, потребитель прогресса нужно будет обновить. Риск принят как осознанный компромисс.

## Миграция данных

Миграция данных не требуется: формат артефактов курса и словарь статусов не меняются.

## Порядок поставки и откат

1. Принятый Planning PR и Spec Baseline в Store
2. Implementation PR в `page` с проверкой и возможностью отката

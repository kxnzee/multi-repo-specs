# Образец требования (для Delta Specs)

Формат по I.7 регламента 3.5.4: нормативное слово в теле требования, стабильный Scenario ID и точное имя операции дельты.

```markdown
## ADDED Requirements

### Requirement: Отображение статуса роли
Система MUST отображать текущую роль сотрудника в карточке профиля.

#### Scenario: PILOT-003 Роль назначена
- GIVEN сотрудник с назначенной ролью «Оператор»
- WHEN открывается карточка профиля
- THEN в поле «Роль» отображается «Оператор»

#### Scenario: PILOT-004 Роль не назначена
- GIVEN сотруднику роль не назначена
- WHEN открывается карточка профиля
- THEN в поле «Роль» отображается «Не назначена»
```

## Что делает этот образец правильным

- `## ADDED Requirements` — точное имя операции OpenSpec.
- `MUST` стоит в первой строке тела требования.
- Scenario ID соответствует `<ПРЕФИКС>-<NNN>` и сохраняется при дальнейших изменениях.
- Каждый сценарий содержит `GIVEN`/`WHEN`/`THEN`.

Технический критерий релизного флага записывается отдельно в Work Package `enables`, например `AC-001`; Scenario ID у такого пакета нет.

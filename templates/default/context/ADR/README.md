# Architecture Decision Records

ADR фиксирует одно явно принятое долговечное техническое решение. Кандидаты на
решение остаются TODO в `../03-architecture.md` до подтверждения.

ADR создаётся только когда одновременно подтверждено, что решение трудно отменить,
без объяснения оно будет неожиданным для будущего читателя и выбор сделан между
реальными альтернативами. Изменение Master Spec само по себе не является основанием
для ADR: Spec фиксирует WHAT, а ADR обязан сохранить принятое решение и WHY. Источником
могут быть принятый Design, явное owner decision или maintained architecture document.

Для change/spec/domain-scoped проверки используйте `/openspec-base-context audit`.
Команда только предлагает ADR candidate и точный diff; файл создаётся после отдельного
подтверждения решения и записи.

Имя файла: `NNNN-short-title.md`.

```md
# ADR-NNNN: Название решения

## Status

Accepted

## Context

Почему потребовалось решение.

## Decision

Что решено.

## Alternatives considered

Какие варианты рассмотрены и почему не выбраны.

## Consequences

Какие положительные и отрицательные последствия приняты.

## Related context

Связанные context-файлы, Specs, Changes, документы или исходный код.
```

# Architecture Decision Records

Здесь сохраняются причины принятых решений о бизнес-границах приложения или
применении ограничений. Действующее описание остаётся в тематическом разделе,
ADR ссылается на него. Технические решения ведутся вне бизнес-контекста.

ADR создаётся только когда одновременно подтверждено, что решение трудно отменить,
без объяснения оно будет неожиданным для будущего читателя и выбор сделан между
реальными альтернативами. Изменение Master Spec само по себе не является основанием
для ADR: Spec фиксирует WHAT, а ADR обязан сохранить принятое решение и WHY. Источником
может быть подтверждённое решение владельца; из Design берётся только решение
о бизнес-границах или ограничениях, без технических подробностей.

Имя файла: `NNNN-short-title.md`.

```md
# ADR-NNNN: Название решения

## Status

Accepted

## Context

Почему потребовалось решение.

## Decision

Что решено.

## Alternatives considered

Какие варианты рассмотрены и почему не выбраны.

## Consequences

Какие положительные и отрицательные последствия приняты.

## Related context

Внутренние ссылки на архитектуру и ограничения этого контекста.
Происхождение решения: название источника, версия/дата и подтверждение — текстом.
```

# Бизнес-ограничения и кибербезопасность

Здесь один раз фиксируются подтверждённые условия, заданные бизнесу приложения
извне: организационные ограничения, правила работы с данными, доступом и передачей
информации. Сюда добавляются применимые ограничения службы кибербезопасности.
Алгоритмы шифрования, сетевые настройки и детали реализации не входят в бизнес-контекст.

## Условия

Каждое условие запишите один раз по форме ниже. Для большого набора допустимы документы
в `constraints/` внутри контекста; здесь остаётся только навигация.

```text
ID и название:
Содержание: применимое условие, понятное без внешнего документа
Область применения: участники, бизнес-данные или процессы
Происхождение: название, пункт, версия/дата — текстом, без URL и пути
Подтверждение: ответственный, его полномочие, дата
```

Поведение приложения для выполнения условия принимается в Specs.
Если нужна классификация чувствительности данных, определите её здесь один раз.
Не выдумывайте сроки хранения, разрешённые действия и исключения.

## Исключения и пробелы

Исключение хранится рядом с условием: принятое отклонение, область, срок и подтверждение
уполномоченного владельца. Редактирование записи не создаёт разрешение.
Если применимое содержание или его принятие неизвестно, оставьте TODO с владельцем.
[Бизнес-процессы](04-business-processes.md) ссылаются на условие, не копируя его.

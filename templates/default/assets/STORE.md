# Центральный OpenSpec Store

Этот репозиторий хранит спецификации и согласованные решения проекта. Он не является
Code Repository или репозиторием разработки OpenSpec Orchestrator.

## Перед началом работы

1. Прочитай `openspec-orch.yaml`: он определяет Store, зарегистрированные Code
   Repositories, выбранного агента и подключённые Extensions и Plugins.
2. Начни знакомство с контекстом через `openspec/context/00-start-here.md` и открывай
   только относящиеся к задаче материалы.
3. Для существующего Change определи его точный ID и schema. Получи актуальное
   состояние, инструкции артефакта и следующий шаг через Orchestrator MCP согласно
   правилам подключённого gateway. Не выбирай Change или следующий шаг по догадке.

## Источники истины

- Requirements, Master Specs и Changes находятся в `openspec/` этого Store.
- `openspec/config.yaml` и schema выбранного Change определяют содержательные
  правила и зависимости артефактов. Не смешивай workflow разных schemas.
- Подтверждённые долговечные знания и принятые ADR находятся в `openspec/context/`.
  Материалы `_raw/` требуют проверки и не становятся фактами автоматически.
- Код и выполненные тесты подтверждают текущее состояние реализации. Они не заменяют
  принятые требования и решения владельца.

## Границы работы

Реализация выполняется в зарегистрированных Code Repositories по принятому scope
Change. Не создавай в них локальные `openspec/changes/`. Перед переходом к коду
подтверди repository ID, checkout и revision; соблюдай локальные инструкции этого
Code Repository и ограничения стадии выбранной schema.

Requirements и Scenarios описывают наблюдаемое поведение и публичные контракты.
Допустимые технические детали Design и execution artifacts определяет их schema;
не переходи к следующей стадии автоматически после завершения отдельного skill.

Сохраняй пользовательские изменения. Не перезаписывай существующие артефакты шаблоном,
не меняй schema активного Change и версию конфигурации без явного согласования.
Не изменяй встроенные OpenSpec skills и команды.

Результат агента или успешные тесты не заменяют человеческий Gate. Публикация,
слияние, Archive, UAT и Release следуют принятому процессу проекта и требуют
соответствующего полномочия или решения. Не придумывай имена веток и направления PR.

## Где находятся подробные правила

- Начальная навигация: `openspec/context/00-start-here.md`.
- Процесс поставки проекта: `openspec/context/08-release-process.md`.
- Workflow, команды и специализированные проверки: подключённые Extensions.
- Требования конкретной стадии: актуальные OpenSpec instructions выбранного Change.

Этот файл содержит общие ориентиры. Не копируй сюда инструкции разработки
Orchestrator, тексты skills или полные правила отдельных стадий.

# Схема артефакта `impact-and-design.md`

**Назначение:** формальная проверка структуры черновика и закрытой версии `impact-and-design.md` (I.14.1 + I.14.2 + I.15 в одном файле, раздел 3 профиля Pilot Core).
**Статус:** ручная валидация на первом пилоте (день 5 — `sdd check --change`). Схема фиксирует обязательные секции и поля, а не проверяет их машиной.

---

## Обязательные секции (в этом порядке)

1. `# Impact and Design: <change-id>`
2. `## Candidate Repositories` — машиночитаемый блок:
   ```yaml
   candidate_repositories: [ui, backend, configuration]
   ```
   Заполняется на стадии черновика (I.14.1). `sdd fetch-repos` читает список **только отсюда**.
3. `## Read Log` — ссылка на `read-log.md` или встроенная таблица «репозиторий → ревизия → дата» после стадии чтения (I.14.2).
4. `## Confirmed Repositories` — итоговый (может отличаться от кандидатов) состав после чтения, с обоснованием каждого добавления/исключения.
5. `## Contracts` — контракты между репозиториями (API, схемы данных, события). Пусто — недопустимо; если контрактов нет, пишется явно: «Контрактов между репозиториями нет».
6. `## Design` — **обязателен даже когда пуст**. Если новых межрепозиторных решений нет: ровно одна строка «Новых межрепозиторных решений нет». Отсутствие раздела — ошибка схемы.
7. `## Deployment and Rollout` — порядок развёртывания по репозиториям, зависимости между релизами.
8. `## Rollback` — процедура отката по каждому репозиторию.

## Правила валидации

| Правило | Тип нарушения |
|---|---|
| Секция `Design` отсутствует | HARD — блокирует Planning PR |
| `candidate_repositories` — не валидный YAML-список | HARD |
| `Confirmed Repositories` не является подмножеством `candidate_repositories` без объяснения добавления | HARD |
| `Contracts` пуст без явной строки-заглушки | WAIVABLE — предупреждение |
| `Rollback` отсутствует для репозитория из `Confirmed Repositories` | HARD |

## Связь с `fetch-repos`

Если после чтения требуется ещё один репозиторий — он дописывается в `candidate_repositories`, и `sdd fetch-repos` перезапускается. Список рассмотренных кандидатов сам по себе становится артефактом (раздел 7 профиля Pilot Core).

# Инструкции для GigaCode

## Контекст центрального Store

- Текущий репозиторий — центральный Store SDD-проекта. Он хранит общие требования, подтверждённый проектный контекст и planning-артефакты; прикладной код реализуется в зарегистрированных Code Repositories.
- Каталог `openspec/` — единственный источник истины для требований и состояния Change: `specs/` содержит принятые требования, `changes/` — активные planning-артефакты, `context/` — подтверждённый продуктовый, доменный и межсистемный контекст.
- `sdd.yaml` описывает совместимую версию OpenSpec, выбранного агента и зарегистрированные репозитории. `.openspec-store/` содержит metadata Store, а `CODEOWNERS` — владельцев нормативных файлов.
- Store не содержит прикладной код, его технологический стек и команды сборки или тестирования. Устойчивый технический контекст каждого Code Repository хранится в его собственном `agent.instructions_file` и читается адресно только на предусмотренном шаге процесса.

## Постоянные ограничения

- Создавай, изменяй и архивируй OpenSpec Changes только в центральном Store. Code Repositories реализуют существующие Changes и не создают собственные каталоги `openspec/changes/`.
- Не переноси локальное устройство кода отдельных Code Repositories в центральные Specs или `openspec/context/`.
- Не изменяй built-in `openspec-*` skills и `opsx-*` commands в provider-specific каталоге агента. Проектные процессы принадлежат файлам `sdd-*` и другим проектным runtime-инструкциям.
- Учитывай владельцев из `CODEOWNERS` при изменении нормативных файлов.
- Не переходи к Archive, пока не завершена реализация во всех затронутых Code Repositories и не выполнены предусмотренные межрепозиторная и ручная проверки.

## Маршрутизация завершённого Planning

`isComplete: true` завершает работу до вызова `openspec instructions` и поэтому не получает

- Если шаг 03 начинается в новой сессии, до первого `/opsx-continue` покажи Change Owner полный `proposal.md` и получи явное подтверждение, что это принятый вход. Не выводи подтверждение из наличия файла или статуса OpenSpec `done`. Не создавай для этого approval-файл и не повторяй Explore, если scope и исходные факты не изменились.
- `isComplete: true` после `/opsx-continue` означает только завершение Proposal, Specs, Design и Tasks, а не готовность реализации.
- В этой ветке замени предложение built-in перейти к `/opsx-apply` или `/opsx-archive` единственным маршрутом: шаг 04, Planning PR и фиксация Spec Baseline. Сам Apply или Archive не запускай.

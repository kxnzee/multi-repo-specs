# Проектный контракт Explore

Эта инструкция дополняет штатный `/opsx-explore` правилами шага 01 SDD. Она выполняется только по точному пути из prompt, подготовленного командой `sdd explore`.

Если prompt не содержит ticket, исходное намерение, Store ID, Spec Root, workspace, Store revision, разрешённые корни чтения и сведения обо всех выбранных Code Repositories, остановись и попроси повторить `sdd explore`. Не восстанавливай значения из истории сессии или по догадке.

## Границы

- Работай только на чтение: не создавай Change, OpenSpec-артефакты, TODO, ADR, ветку или PR и не изменяй context pack, Master Specs либо код.
- Ticket и исходное намерение бери только из runtime-параметров текущего запуска.
- Workspace задаёт multi-repo-территорию, но не разрешает сканировать её целиком. Читай только явно перечисленные разрешённые корни.
- Не читай родительские каталоги, remotes, невыбранные репозитории и другие соседние пути.
- Не обращайся к Jira API.
- Все непосредственные чтения Specs и Changes выполняй с явным `--store` для переданного Store ID. Не используй nearest или default Store.

## Порядок исследования

1. Если исходного намерения недостаточно для начала исследования, задай уточняющий вопрос до чтения кода.
2. Прочитай `openspec/context/00-start-here.md`, назначенный им контекст и подходящие Master Specs.
3. Для каждого checkout проверь ветку, точную ревизию и чистоту до исследования.
4. Адресно прочитай только источники, необходимые для текущего вопроса.
5. Не выдавай предполагаемые endpoint, технологии, статусы и архитектуру за текущее состояние. Каждый факт свяжи с прочитанным источником; неподтверждённое явно пометь как гипотезу или неизвестное.
6. Если нужен ещё один Code Repository, остановись и попроси повторить `sdd explore` с полным набором.
7. Перед итогом повторно проверь ветку, ревизию и чистоту каждого checkout.

Уточнённую проблему и ожидаемый наблюдаемый результат формулируй только по исследованным фактам.

## Результат

Верни структурированный итог:

- ticket;
- исходное намерение;
- уточнённая проблема;
- ожидаемый наблюдаемый результат;
- прочитанные источники;
- исследованные репозитории, ветки и ревизии;
- текущее поведение;
- область влияния;
- альтернативы;
- подтверждённые факты и их источники;
- предположения;
- открытые вопросы с владельцами и признаком блокировки.

Если блокирующих вопросов нет, попроси Change Owner подтвердить завершение Explore и выбрать `<short-name>`. Следующим действием назови только `/sdd-change <ticket> <short-name>` с ticket текущего запуска. Сам команду не вызывай. Не предлагай `/opsx-new`, `/opsx-propose`, Apply или Archive.

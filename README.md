# OpenSpec Orchestrator

OpenSpec Orchestrator помогает ИИ-агентам работать с требованиями и кодом в
нескольких репозиториях. Он связывает центральный репозиторий спецификаций,
репозитории кода и инструменты агента. Видно, какая задача OpenSpec дошла до
реализации и в каком коммите она оказалась.

Сам Orchestrator не управляет моделью, её сессиями и разрешениями. OpenSpec ведёт
требования и жизненный цикл артефактов. Команда отвечает за проверку изменений,
непрерывную интеграцию, развёртывание, приёмку, выпуск и архивирование.

## Требования

- Node.js 22.16.0 или новее;
- npm и Git;
- OpenSpec в `PATH`.

Для работы с моделью нужен настроенный клиент выбранного агента: Claude, Qwen или
GigaCode.

## Что даёт обвязка

| Задача | Возможность |
|---|---|
| Дать агенту общий контекст проекта | Репозиторий спецификаций с требованиями, изменениями, бизнес-контекстом и реестром репозиториев. Контекст доступен через MCP |
| Подготовить рабочее окружение | Подключить репозиторий спецификаций и репозитории кода, передать агенту команды и расширения |
| Выбрать процесс под задачу | Использовать настраиваемые схемы для планирования, реализации и проверки |
| Понять влияние изменения | Посмотреть связи требований, изменений и репозиториев в OpenSpec Graph; исследовать код с CodeGraph |
| Зафиксировать результат реализации | Связать выполненные задачи OpenSpec с коммитами в репозиториях кода |
| Найти проблемы настройки | Запустить `doctor` и получить причины ошибок |

## Механизмы Orchestrator

### Репозитории

Репозитории задают границы владения: где лежит принятый контракт, где пишется
код и откуда команда читает требования других команд. В проекте один основной
репозиторий спецификаций. В нём хранятся основные спецификации, изменения,
контекст и реестр репозиториев. К нему подключаются репозитории кода и, если
нужно, репозитории спецификаций других команд.

Для роли `specs` создаётся отдельная рабочая копия. Её репозитории кода,
вложенные хранилища и пакеты не разворачиваются. Задачи между командами
автоматически не передаются.

| Роль | Назначение | Документация |
|---|---|---|
| `store` | Центральный репозиторий спецификаций с требованиями, изменениями и контекстом команды | [Начало работы](docs/user/getting-started.md) |
| `code` | Репозиторий реализации компонента | [Конфигурация](docs/user/configuration.md) |
| `specs` | Подключённый репозиторий спецификаций другой команды для чтения | [Конфигурация](docs/user/configuration.md#подключённые-store-роль-specs) |

### Шаблоны

Шаблон нужен, чтобы новый репозиторий спецификаций не начинался с пустого
каталога. Он добавляет схемы, контекст и правила процесса. Скопированные файлы
принадлежат команде, их можно подстроить под свой проект.

| Шаблон | Назначение | Документация |
|---|---|---|
| `default` | Базовый шаблон для обычных изменений со схемами `spec-driven-extended` и `superspec-multirepo` | [Шаблоны проектов](docs/user/project-template.md) |
| `initiative` | Шаблон для инициатив нескольких команд без кодовой реализации | [Инициативы](docs/user/initiatives.md) |

### Агенты

Адаптер агента даёт Claude, Qwen или GigaCode доступ к контексту и инструментам
Orchestrator через MCP. При подключении он проверяет, что клиент выбранного агента
доступен. Авторизацию, сессии и разрешения по-прежнему ведёт сам клиент.

| Агент | Назначение | Документация |
|---|---|---|
| Claude | Работа через клиент Claude | [Установка и обновление](docs/user/installation-and-updates.md) |
| Qwen | Работа через клиент Qwen | [Установка и обновление](docs/user/installation-and-updates.md) |
| GigaCode | Работа через клиент GigaCode | [Установка и обновление](docs/user/installation-and-updates.md) |

### Расширения

Расширение помогает агенту соблюдать процесс работы. Оно добавляет инструкции,
навыки, команды и манифесты для конкретных провайдеров. Расширение не принимает
продуктовые решения и не подтверждает результат реализации само по себе.

| Расширение | Назначение | Документация |
|---|---|---|
| `spec-driven-extended` | Процесс для уточнения запроса, сбора вводных, планирования, реализации и проверки | [Шаблоны проектов](docs/user/project-template.md) |
| `superpowers` | Процесс с обсуждением подхода, подробным планом, разработкой через тесты и проверкой изменений | [Шаблоны проектов](docs/user/project-template.md) |
| `orchestrator-agent` | Шлюз агента для доступа к контексту и инструментам через MCP | [Установка и обновление](docs/user/installation-and-updates.md) |

### Плагины

Плагины добавляют исполняемые возможности, которых нет в общем ядре Orchestrator.

| Плагин | Назначение | Документация |
|---|---|---|
| `openspec-graph` | Проверка связей репозитория спецификаций, изменений и требований; граф в браузере и MCP | [Плагины](docs/user/plugins.md#openspec-graph) |
| `codegraph` | Локальная навигация по коду выбранного репозитория | [Плагины](docs/user/plugins.md#codegraph) |
| `change-tracking` | Связь задач OpenSpec с коммитами в репозиториях кода | [Плагины](docs/user/plugins.md#change-tracking) |
